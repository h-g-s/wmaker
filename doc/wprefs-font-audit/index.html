WPrefs font scaling: panel comparison

Captured on 2026-11-04 from commit 89df8885. All 16 enabled top-level preference panels are compared at the original font default (DefaultFontSize = 11), size 18, and size 24.

Result: WPrefs is not yet generally font-size-aware. Its fixed 520 × 390 window and mostly fixed inner control dimensions do not accommodate the larger text and symbols. Many pages already clip at size 18; size 24 makes the failures more pronounced. Growing the outer window alone will not fix fixed-height checkbox rows, labels, or fields.

Capture conditions and limits

  • Separate Xvfb desktops at 1920 × 1080, 24-bit color; identical English locale, repository defaults, and isolated temporary user homes. Only DefaultFontSize changes for sizes 18 and 24. No real user preferences were changed.
  • The repository WPrefs and WINGs builds were used. The recent scalable symbols and button bevels are included. Explicitly sized fonts and image previews may stay small even when the default font grows; this is visible in the comparisons.
  • Every panel was activated through its existing section-button callback and verified by its window title before capture. The icon strip remains at its initial scroll position, so the selected icon for later panels may be off-screen.
  • Each image is an unscaled 520 × 390 client-area screenshot, without the window manager frame. The page scales images to fit your browser; click one to inspect it at native resolution.
  • These are initial views, not an exhaustive audit of every nested tab, popup menu, scroll position, dialog, or setting combination. Search Paths opens on Icon Search Paths; Appearance opens on Texture. Scrollable content beyond the initial viewport needs a separate pass. No saving or preference changes were performed.
  • Red search-path entries refer to directories absent from the isolated home; they are not font-rendering failures. The menu editor's instructions contain the temporary menu-file path, which differs between captures.
